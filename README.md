# PanLens · 百度网盘空间分析器

**把百度网盘的每一块空间都看得清清楚楚**

像 WizTree / WinDirStat / SpaceSniffer 那样，用色块面积直观展示每个文件夹到底占了多少空间

<sub>纯本地运行 · 零第三方依赖 · 只用一个 Python 标准库就能跑</sub>

</div>

---

## 这是什么

网盘用久了，空间总在不知不觉中消失：不知道哪个文件夹最占地方，不知道几百 GB 到底花在哪儿。网盘客户端只会告诉你「已用 800 GB」，却不会告诉你为什么。

**PanLens** 解决的就是这个问题。它列举你网盘里的全部文件，算出每个文件夹的真实体积，然后用 **Treemap（矩形树图）** 画出来——**色块面积严格等于字节占比**，一眼就能看出谁是大头。

所有请求都从你自己的电脑直接发往百度网盘，不经过任何第三方服务器，也不上传任何数据。

## 功能

| 能力 | 说明 |
| :--- | :--- |
| **扫码登录** | 手机百度 APP 扫一扫即可登录，不用手动复制 Cookie |
| **Treemap 可视化** | Squarified 算法，支持 1~4 层细分；面积 = 体积，颜色 = 文件类型 |
| **逐层钻取** | 点色块进入子目录，面包屑 / `Backspace` 返回上级 |
| **悬停详情** | 完整路径、体积、占当前目录比例、文件数 |
| **外框标注** | 展开的文件夹在标题栏显示 `名称 + 体积 + 占比` |
| **其他项展开** | 被合并的「其他 N 项」点一下即放大成独立视图，可继续查看 |
| **明细表格** | 可排序，带占比进度条，支持勾选与全选 |
| **选中删除** | 勾选后二次确认，移入网盘回收站（可恢复），删完自动更新索引 |
| **类型分布** | 按扩展名归类统计，堆叠条 + 排行 |
| **最大文件榜** | 当前目录体积 Top 12，点击跳到所在文件夹 |
| **全局搜索** | 按文件名搜索整个索引，点击定位 |
| **导出报告** | CSV 清单（Excel 直接打开）+ **自包含 HTML 报告**：类型分布、Top 文件、可折叠目录树，可分享或打印成 PDF |
| **本地缓存** | 扫描结果落在 SQLite，关掉重开秒开，不必重复扫 |
| **实时进度** | 扫描时显示文件夹数 / 文件数 / 累计体积 / 当前路径，可随时中断 |

## 快速开始

**环境要求**：Python 3.9 及以上（Windows / macOS / Linux 均可），无需 `pip install` 任何东西。

```bash
git clone https://github.com/BILSON093/panlens.git
cd panlens
python run.py
```

Windows 用户也可以直接**双击 `启动.bat`**，会自动打开浏览器。

默认地址 <http://127.0.0.1:8765>，端口被占用时会自动往后顺延。

```bash
python run.py                # 默认 127.0.0.1:8765
python run.py --port 9000    # 指定端口
python run.py --no-browser   # 不自动打开浏览器
```

不想登录也能先看效果：首页点 **「先看演示数据」**，会载入一份虚构的网盘目录树。

## 登录方式

### 方式一：扫码登录（推荐）

1. 点右上角 **「登录网盘」**，默认就是「扫码登录」标签页
2. 手机打开 **百度 APP** 或 **百度网盘 APP** → 右上角 **扫一扫**
3. 手机上点 **确认登录**，页面会自动登录并开始扫描

二维码约 5 分钟过期，可点「换一张二维码」即时刷新；多个标签页会共用同一张码。

### 方式二：网页 Cookie

1. 浏览器打开 <https://pan.baidu.com> 并登录
2. `F12` → **Network（网络）** → 刷新页面 → 点开任意一条发往 `pan.baidu.com` 的请求
3. 在 **Request Headers** 里复制 `Cookie` 整段值，粘贴到弹窗的「网页 Cookie」标签页

### 方式三：开放平台 access_token

在 <https://pan.baidu.com/union> 注册应用并申请网盘权限（scope 含 `basic,netdisk`），
走 OAuth 拿到 `access_token`，粘贴到第三个标签页。有效期约 30 天。

### 三种方式的权限差异

| 登录方式 | 读取 / 扫描 | 删除文件 | 显示网盘总容量 |
| :--- | :---: | :---: | :---: |
| 扫码登录 | ✅ | ❌ | ❌ |
| 网页 Cookie | ✅ | ✅ | ✅ |
| 开放平台 Token | ✅ | ✅ | ✅ |

> 扫码拿到的凭据只够读取，写入类接口（删除）会被网盘拒绝；容量接口同样不认这类会话。
> 这两项在扫码登录时界面会明确提示，需要时换成网页 Cookie 即可。原因见[已知限制](#已知限制)。

## 界面说明

```
┌─ 顶栏：面包屑路径 · 容量 · 扫描 · 登录 ───────────────────────────────┐
│                                                      │ 账号容量      │
│   Treemap 色块区                                     │ 当前目录概览  │
│   面积 = 体积，颜色 = 文件类型，点哪层进哪层          │ 类型分布      │
│                                                      │ 最大文件      │
├─ 明细表格：勾选 · 名称 · 大小 · 占比 · 文件数 · 时间 ─┤ 搜索          │
└──────────────────────────────────────────────────────┴───────────────┘
```

- **顶部「细分」** 控制色块的展开层数：层数越少块越大越好认，层数越多信息越密。
- **色块上的文字** 带深色描边，压在任何底色上都清晰；细高的格子会竖向排字。
- **勾选框** 支持单选 / 全选，选中后表格上方出现操作条，可一键移入回收站。

## 工作原理

1. **列举目录**：网页接口 `GET /api/list`（`page` + `num=1000` 翻页），
   或开放平台 `GET /rest/2.0/xpan/file?method=list`（`start` + `limit=1000`）。
2. **并发遍历**：4 个线程并发拉取目录列表，带随机抖动与指数退避重试，避免触发风控。
3. **体积汇总**：接口返回的文件夹 `size` 恒为 0，所以必须递归到底。
   扫描结束后按深度倒序做一次自底向上汇总：
   `目录体积 = 直属文件体积 + 子目录体积`，结果连同文件数写入 SQLite。
4. **前端渲染**：标准 squarified treemap 递归布局，配合最小面积聚合、
   节点数量上限与三级标签降级（横排 → 竖排 → 首字），保证上万条目也不卡、不留空白块。

## 常见问题

**登录报「BDUSS 看起来不完整」**
只复制了一部分。要在 Network 面板的 Request Headers 里复制**整段** `Cookie`。

**扫码后一直显示「已扫码」不动**
手机上还需再点一次「确认登录」。二维码过期（约 5 分钟）就点「换一张二维码」。

**删除按钮报「当前登录会话没有删除权限」**
扫码登录的凭据只够读取。换「网页 Cookie」或「开放平台 Token」登录即可删除。
本程序只做「移入回收站」，不会永久删除，删错了可以去网盘回收站恢复。

**扫描很慢 / 中途停止**
文件越多越慢，接口每次最多返回 1000 条。全盘扫描通常几分钟到几十分钟，
中途点「停止」也能看到已扫完的部分。

**扫描结果和网盘显示的容量不一致**
网盘的「已用容量」还包含回收站、隐藏目录等，树里看不到，差异通常来自那里。

**换账号 / 想强制重扫**
点「重新扫描」即可，会清空该根目录下的旧索引再重建。

## 已知限制

- **扫码会话不能删除、也拿不到总容量**。同一份 Cookie 下 `/api/list` 完全正常，
  但 `/api/quota` 与 `/api/filemanager` 恒定返回 `errno -6`。试过补 `bdstoken`、`PANWEB=1`、
  `BAIDUID`、切换 GET/POST 与 Referer 均无效，推测扫码得到的是 API 级凭据而非完整网页会话。
  需要这两项能力时请用网页 Cookie 登录。
- 深度越深、格子越小，可读性必然下降。程序会自动合并过小的格子并支持展开查看，
  但 Treemap 本身就是「看得见趋势、看不清每一个」的取舍。
- 只支持百度网盘，未适配其他网盘服务。
